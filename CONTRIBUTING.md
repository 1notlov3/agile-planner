# Правила работы с репозиторием

## Ветки

| Ветка | Назначение | Кто изменяет |
|---|---|---|
| `main` | выпущенные версии (теги v1.0, v1.0.1) | руководитель проекта через pull request |
| `develop` | интеграция завершённых работ | слияние из рабочих веток через pull request |
| `docs/analysis` | инициация, требования, ТЗ (ИСР 1–2) | аналитик |
| `docs/design` | проектирование (ИСР 3) | аналитик, разработчик |
| `feature/*` | итерации разработки (ИСР 4) | разработчик |
| `test/*` | тестирование (ИСР 5) | тестировщик |
| `release/*` | подготовка выпуска (ИСР 6) | руководитель проекта |
| `hotfix/*` | исправления после выпуска (ИСР 7) | разработчик |

## Роли и права доступа на GitHub

| Роль в проекте | Роль GitHub | Права |
|---|---|---|
| Руководитель проекта | Admin | настройки, правила защиты веток, слияние в main |
| Ведущий разработчик | Maintain | слияние pull request в develop, управление issues |
| Аналитик, разработчик | Write | push в рабочие ветки, создание pull request |
| Тестировщик | Triage | issues, метки, назначение ответственных |
| Заказчик, пользователь | Read | просмотр кода, создание issues |

Прямой push в `main` и `develop` запрещён правилами защиты веток.
